## Exceptions

Intended changes that move guarded behaviour or compatibility. Approver: the author's request of 2026-11-18 ("do all of the crossover
work saved for 2.0 that breaks ids and such"), with the throttle body decided as keep. Not yet reviewed line by line.

- **Advancement IDs.** All 110 1.x IDs are gone. 64 rows plus the root are redefined as `<track>/<row>` (`root` for the tab root,
  `chief_engineer` unchanged); 46 hidden rows deleted. `AdvancementTabTest` was rewritten by hand (it pinned 110 files "deleted in
  2.0, not in 1.x"). `driveline/every_gear` is now shown. Progress carries over by `AdvancementMigration` and the
  `PlayerAdvancementsMixin`. Anything referring to an old ID (datapacks, commands, other mods) breaks.
- **Config files and keys.** New files `create_engines-v2-server.toml` and `create_engines-v2-client.toml`; `[engine]` split into
  `[calibration]` and `[limits]`; client `[effects]` split and four keys renamed. A pack's `defaultconfigs/create_engines-server.toml`
  no longer applies. Presets still copy over (`[balance]` and `[features]` unchanged).
- **Create 6.0.10 dropped.** Needs 6.0.11 or newer; the jar metadata range is `[6.0.11,6.1)`.
- **Altitude thinning.** Engines above y 128 make less power by default (`compat.altitudeThinning`). Existing builds at or below y 128
  are unchanged; `compat/behaviour.txt` and `compat/trajectories.txt` did not move. Not guarded by a new baseline entry.
- **Port count curve.** `PortNetwork.flowFactor()` is now `PortFlow.factor`: diminishing returns per opening, crowded openings worth half.
  Every engine with under about two openings per head breathes less (one per head: 90 percent, was 100; one for two heads: 67 percent,
  was 100). `compat/behaviour.txt` and `compat/trajectories.txt` did not move (they set the factor directly). Not guarded by a baseline
  that sees real layouts. The constant 2.3 is a first choice from a six-cylinder sweep.
- **GameTest guard moved by hand.** `aVariableTurbochargerClosesItsVanesOnAThinExhaust`: vanes floor 0.2 to 0.15 (measured 0.177 with the
  one-opening-per-head build, which now breathes at 90 percent). An attempt to keep the old bound by adding extra mouths did not join the
  pipes in the test, so the bound moved instead. Approver: the author's request of 2026-11-18 for the port curve; not reviewed line by line.
- **Create floor restored to 6.0.10** (author, 2026-11-18): Aeronautics 1.2.1 and 1.3.2 both crash on Create 6.0.11, so the range is
  back to `[6.0.10,6.1)` and the "Create 6.0.10 dropped" exception above no longer stands. The build is on Create 6.0.10-281, NeoForge
  21.1.228 (for Aeronautics 1.3.2 and Sable 2.0.6; the mod's own range is unchanged).
- **API frozen at 1.0.0.** Public methods that were internals (`reportFailuresTo`, `reportSourceFailure`, `blockChanged`, `sourcesFor`)
  moved from `api.EngineExtensions` to `engine.EngineProviders`; they were preview and for the engine and tests only.
- **Precision parts as data.** `CylinderSpec.build` reads `PartEffects`; the built-in numbers are bit-for-bit the same.
- **Test changes.** `ConfigMatrixTest` gained the `altitudeThinning` switch (a new setting, nothing loosened).
- **Casing dye moved from block state to block entity.** The `paint` property is gone from the cylinder, crankshaft (and crank
  throw, rotor housing), camshaft (and cam lobe), the two manifolds, and the cased shafts and cogwheels of all four casing styles. Each
  holds its dye in its block entity under `Paint` (the manifolds gained a block entity, `create_engines:manifold`, that only holds
  the dye; the cased shaft and cog block entity types are now subclasses). The plain Engine Casing blocks keep `paint` as state, so
  `compat/manifest.txt` (`prop:EngineCasingBlock:paint`) did not move. Block states per pipe fall 17-fold. A world saved before this
  keeps its dye: `PaintMigration` reads the old `paint` out of the raw chunk palette on `ChunkDataEvent.Load` and writes it into the
  block entity data (tested by `PaintMigrationGameTests`, which rewrites a real saved chunk to the 1.x layout and loads it through the
  game's chunk reader, and by `PackedPaletteTest`). **Not migrated:** a part inside a moving contraption saved at upgrade time, and
  parts in saved structure or schematic files, lose their tint (they carry states with no position); the part itself works as before.
  Tint is read from the block entity in the block colour handler; not yet looked at by eye (plain, Flywheel, Sodium, contraption).
  Ran: unit tests 1183 (1 red, the other session's `ArchitectureRulesTest`), GameTests 333 passed (6 new), `pitest` 169 survivors
  plus 1 unreached, at the limit of 170.
- **Pollution of the Realms: sulfur field, Soot Trap, rates, bridge fix** (author's decisions of 2026-11-19, rates Claude's call).
  `FuelSpec` gained an eighth component `sulfur` (the seven-argument constructor is kept and sets it to the soot factor); the fuel
  data map gained an optional `sulfur`; a Soot Trap's caught soot is taken off the extra rich-running carbon
  (`SootTrapBlockEntity.catchSoot` now returns what it kept). `Emissions.CARBON_PER_MB` 0.02 to 0.5 and `SULFUR_PER_MB` 0.01 to
  0.25, from a measured one-cylinder diesel (see ROADMAP). `PollutionBridge` now puts each gas in its own cell (sulfur had been
  refused by the cell the carbon filled). Nothing in the simulation reads any of it: `compat/behaviour.txt` and
  `compat/trajectories.txt` did not move. `EmissionsTest` was updated by hand: its exact-number checks used inputs sized for the
  old constants, which now hit the 64-step cap, so each input was scaled down and its meaning kept; nothing was loosened.
  New: `PollutionGameTests` (7 asserting: running diesel, ethanol, cranked, switched off, shut or flooded outlet, Soot Trap on a
  rich pair, and a two-engine comparison of what each outlet was offered; 2 measuring), `PollutionProbe`, tests for the sulfur
  fallback and `caught`/`escaped`. Changed on the strength of them: `PollutionCompat.release` no longer releases into a mouth with
  fluid in front of it (an engine coasting under water leaked gas through it). Each of the two guards that matter was checked by
  breaking it: with the trap wiring removed the trap test failed (51 carbon on both engines), and with the water check removed
  the shut-outlet test failed (3 steps through the water).
  Ran: unit tests all green, GameTests 343 passed both with Pollution of the Realms 9.1.14.0 and without, `pitest` 169 live plus
  1 unreached at the limit of 170 (three boundary mutants in the first draft of `caught`/`escaped` were equivalent, so those two
  were rewritten without a comparison, not left to raise the limit). Not tuned beyond the one engine.
- **NeoForge minimum stays 21.1.219.** The build moved to NeoForge 21.1.228 (for Aeronautics 1.3.2 and Sable), and the mod's own metadata
  took that as its minimum, so the first jar would not load on 21.1.219 (found by booting it). `neo_min_version=21.1.219` is now separate
  from `neo_version`, so building on a newer NeoForge does not raise what players need.
- **Not done from the saved-for-2.0 list:** legacy manifold handling (nothing found; `Gears.fromLegacy` kept because 2.0 still opens
  1.0 worlds), the basin fuel recipe review, most of the Aeronautics moving-structure work (only the world-height piece is written, and it has never run: see ROADMAP), the optimization pass.
- **Aeronautics row broken by the Create floor.** Aeronautics 1.2.1's bundled Simulated fails to load on Create 6.0.11 (mixin target `NixieTubeBlock.getPower` missing). `runGameTestServerSable`, `runSmokeAuditAeronautics` and the showcase need a NeoForge 21.1.228+ build and Aeronautics 1.3.2, or the row stays red.
