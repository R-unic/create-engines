Create 6.0.10-281, NeoForge 21.1.228 (server boot 21.1.219). **The gate found one failure, and one older flaky check is still open:**

1. `runGameTestServerPollution`: `anEngineWithItsPollutionSwitchedOffReleasesNothing` failed (6 carbon). It failed again under a probe, and the debug log showed why: the preset
   command test saved `expert` to the config file and put back only the values in memory; the file watcher read the file again about half a second later, in the middle
   of the pollution test, and switched pollution back on. A fault of the tests, not of the mod. Fixed in the tests: both preset tests now save the restored values and
   the pollution test saves its switch. No assertion changed. Rerun: Pollution and the main GameTests, 602 each, passed.
2. `everyNetworkCodecRoundTripsAndRejectsBadBytes` passed in every run of this gate, but it has failed its 750 ms wall-clock limit in earlier copies (0.8 s to 15.6 s,
   `fuel data map sync` and `jerry can fluid`). Measured in a probe run on the input that once took 15.6 s: 6 bytes, 174 ms wall, 78 ms CPU, 3.4 MB allocated, so the
   time is the machine stalling (collection pauses seen on other inputs; about 2 GB of memory was free). STABILITY.md 1.4 wants it fixed or dropped. **Not changed:**
   the proposed fix times the decoding thread's CPU instead of the clock, with the same limit, which would no longer see a decode that sleeps or blocks. It needs the
   author's decision, and the GameTest box stays open until then. The author reported on 2026-11-25 that their game was open during the gate, and gave that as the
   cause of any performance failures; a `javaw` process holding about 9 GB was seen at the time. The metrics below were measured with it running.
