# Log lines the smoke verification ignores, as regular expressions matched anywhere in the line.
# Every entry needs a comment saying WHY it is harmless. If you cannot say why, it is a bug, not noise.
# When the environment changes (a new Create or NeoForge version) re-check each entry and delete the ones
# whose reason no longer holds, so a real problem cannot hide behind a stale excuse.

# The dedicated server (the GameTest server) logs an ERROR with a NoSuchFileException when run/gametest/server.properties does
# not exist yet, which is every first run in a fresh checkout or private copy; it writes the file itself and never logs it again.
# Without this entry the release gate fails on its first run for a reason that is not a defect. Matches only that file.
Failed to load properties from file: server\.properties

# NeoForge's own FluidStack loader logs this ERROR when a saved fluid amount is negative and then loads an empty fluid. The GameTest
# churn (StressWorldGameTests, seeds 1 to 6) reloads block entities from deliberately mangled saves, and its mutation mode 2 turns every
# saved integer into -abs(n) - 1, so a tank that held 522 mB reloads as -523. Whether a given run writes one depends on the seeded
# random picks, which move whenever a block is added to the mod (found when methanol was added, 2026-11-21; kerosene did not hit it).
# Harmless: the line is NeoForge's response to the corrupt save, and the engine carries on with an empty tank (the test checks that).
# Matches only this message with a negative value, so any other fluid-loading error still fails the run.
Tried to load invalid fluid: 'Value must be positive: -\d+'

# Only in the EMI compatibility row. EMI logs an ERROR for each tag it cannot find a name for. Four of the tags in the
# game belong to Create, NeoForge and Curios, not to this mod (the chocolate and tea convention tags and curios:head), so
# naming them is not ours to do; the message is a cosmetic notice and changes nothing in the game. This mod's own tags are
# named in CELang and are deliberately not listed here, so a new tag of ours without a name fails the EMI row. Matches
# exactly these four.
\[EMI\] Untranslated tag #(c:buckets/chocolate|c:drinks/tea|c:foods/chocolate|curios:head)$

# Only in the Create Aeronautics compatibility row. Simulated (the physics mod bundled in the Aeronautics jar, 1.2.1) ships
# the model simulated:block/rope_connector/block_horizontal with "parent": "block", which resolves to minecraft:block, a model
# vanilla does not have. The bake logs a WARN and the game draws that one block's model as missing. It is a defect in
# Simulated's own asset, found by reading the model in its jar; this mod has no part in it and nothing of ours is drawn
# wrong by it. Matches only this model and only this missing parent, so any other model that fails to load, ours or
# another mod's, still fails the row. Delete it when Aeronautics ships a fixed Simulated.
Unable to load model: 'minecraft:block' referenced from: simulated:block/rope_connector/block_horizontal:
